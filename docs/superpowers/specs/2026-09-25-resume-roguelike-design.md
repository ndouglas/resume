# Résumé Roguelike: Design

Date: 2026-09-25
Status: Approved in discussion; awaiting review of this document

## 1. Purpose

A browser game, in the manner of Ball x Pit (brick-breaker crossed with a
roguelike), built from the résumé's content database and published beside the
PDF at `https://ndouglas.github.io/resume/game/`.

Audience: recruiters and hiring engineers. Success means a visitor who plays
for five minutes leaves having read several real bullets, understood the
SRE/platform throughline, and seen a link to the PDF and a way to get in touch.
A visitor who does not want to play can reach the résumé in one click.

The mechanics are SRE, infrastructure, and system-design metaphors, so the game
itself carries the throughline: makes production systems safe to change, finds
what is silently wrong, ends up owning the system.

## 2. Constraints

- **Evidence-backed only.** Bullet text appears verbatim. Every enemy, boss,
  and fusion cites the bullet id it is drawn from, and a test fails if the id
  does not exist. No invented accomplishments in flavour text.
- **Sensitivity rule** (spec 2026-09-11 §3) applies to every string in the
  game design file, enforced by the existing `tunable.sensitivity` lint: no
  dollar amounts, no outage durations, no blame language.
- **No build toolchain.** Plain ES modules and Canvas 2D; no npm dependencies,
  no bundler. Tests use `node --test` (Node ships on `ubuntu-latest`).
- **Boring pipeline.** Game data is generated from `content/` by Python, the
  same way the PDF is; editing a bullet updates the game on the next deploy.

## 3. Layout

```
game/
  index.html          # shell, canvas, overlays (cards, pause, postmortem)
  style.css
  src/
    main.js           # boot: fetch game-data.json, wire input, start loop
    engine.js         # fixed-timestep loop, state machine (title/play/levelup/boss/postmortem)
    physics.js        # ball–wall, ball–enemy (circle vs rect) collision; pure
    balls.js          # ball kinds and their on-hit behaviours; pure
    enemies.js        # enemy kinds and behaviours; pure
    stages.js         # wave schedule per stage, boss scripts; pure
    cards.js          # tag → effect derivation, card draw; pure
    fusion.js         # fusion recipes; pure
    postmortem.js     # run timeline and DORA-style stats; pure
    render.js         # all canvas drawing; the only module touching the DOM besides main/ui
    ui.js             # DOM overlays
    rng.js            # seeded PRNG so runs and tests are reproducible
  design.yaml         # hand-authored game design: balls, enemies, bosses, fusions, tag effects
  test/*.test.js      # node --test
tunable/game.py       # export content + design.yaml → game-data.json
tests/test_game.py    # design validation (ids exist, tags covered, sensitivity)
```

`build.py --all` (and a new `build.py --game`) writes `dist/game/`, copying
`game/` minus `design.yaml` and `test/`, plus the generated `game-data.json`.
CI already uploads `dist/`, so the deploy step is unchanged. The `test` job
gains a `node --test game/test/` step.

The pure modules take state and return state or events; they never touch the
DOM or canvas, so the headless simulation test can drive a whole run.

## 4. Data: `game-data.json`

Generated by `tunable/game.py`:

- `person`: name, website, GitHub, LinkedIn, the default profile's email,
  the `commercial` summary, and `resume.pdf` URL.
- `roles`: for each role, id, title, employer, dates, and its bullets
  (id, text, tags, weight).
- `projects`: id, name, emoji, text, url.
- `design`: `design.yaml` passed through after validation.

The loader (`tunable.loader.load_content`) is reused so the game sees exactly
the validated content the PDF does.

## 5. Core loop

The Pit is production. The player is the service at the bottom edge; aim with
mouse or touch, fire balls that bounce off walls and enemies and return to the
player when they reach the bottom edge (Ball x Pit rules: a ball is available
to fire again once it returns).

Enemies are failure modes descending in rows. An enemy crossing the bottom
line **burns error budget** by its damage value. Error budget is hit points;
at zero the run ends with **SLO breached**. Clearing the final boss ends it
with **SLO met**. Either way the postmortem follows.

Killing enemies drops XP ("merged PRs"). Each level-up pauses play for a
card choice (§8).

Target run length: 5–8 minutes for a winning run on first-time skill.

## 6. Stages and bosses

Four stages in career order. Each stage is a wave schedule (roughly 90 s)
followed by its boss. The stage banner shows employer, title, and dates.

| # | Stage | Boss | Mechanic | Cites |
|---|---|---|---|---|
| 1 | DEVONtechnologies | The Sync Conflict | At half health splits into two replicas that drift apart; if both are not killed within a window they re-merge at full combined health. | devon-owned-sync |
| 2 | Convention News | The Managed Host Invoice | Grows slowly and gains health over time; damage from `migration`-effect cards counts double. | ain-arc |
| 3 | VA.gov CMS | Drupal 8 → 9 → 10 | Three phases; each "upgrade" changes its movement and spawns a module-row shield that must be broken first. | cms-sse-drupal9, cms-tl-drupal10 |
| 4 | VA.gov Check-In | The Hard Cutover | Alternates between two halves of the pit ("accounts"); traffic waves continue during the fight at rising rate. | cie-account-cutover, cie-ownership |

## 7. Enemies and balls

### Enemies

| Enemy | Behaviour | Cites |
|---|---|---|
| Request | Basic unit; arrives in bursts ("traffic spikes"). | cie-ownership |
| Flaky Test | Phases in and out; while phased, balls pass through. | cms-sse-flaky |
| Silent Defect | Invisible and unhittable until revealed by an observability hit or reveal radius. | cie-silent-defect |
| Long-lived Credential | Armoured; takes 10% damage except from security damage. | cie-credentials |
| Idle Capacity | Large, slow, harmless to budget; big XP bonus ("cost savings"). | cie-cost |
| Deadlock | Spawns as a linked pair; if one dies and the other survives 2 s, the dead one respawns. | cms-sse-flaky |
| Unpinned Dependency | Spawns a copy every few seconds while alive. | cie-dependency-hygiene |
| Skipped Check | Appears greyed out ("counted as a pass"), ignores hits until revealed. | cie-dependency-hygiene |

### Balls

The player starts with one ball and is offered new kinds on level-up (as a
card slot alongside bullet cards). Each kind levels 1–3.

| Ball | Behaviour |
|---|---|
| Lambda | On hit, spawns short-lived concurrent copies (scale-out). |
| Datadog | Marks hit enemies as traced (+50% damage taken); reveals Silent Defects and Skipped Checks. |
| Terraform | Idempotent: pierces and deals full damage on repeat hits. |
| OIDC | Security damage; breaks credential armour. |
| Cypress | Pins Flaky Tests solid for several seconds. |
| Redis | Chance of a cache hit that repeats the damage for free. |
| Rust | Heavy, slow, pierces everything, fixed deterministic damage. |
| PagerDuty | Homes toward the enemy nearest the bottom edge. |
| GitHub Actions | Matrix: fires as a fan of shards that each rejoin on return. |

### Fusions (system design)

Two ball kinds at level 3 may fuse (offered as a card). The fused ball has both
behaviours plus a bonus, and its card shows the cited bullet verbatim.

| Fusion | Parts | Bonus | Cites |
|---|---|---|---|
| Self-describing Lambda | Lambda + Terraform | Copies inherit pierce. | cie-self-describing-lambda |
| Zero Long-lived Credentials | OIDC + GitHub Actions | Security damage to everything. | cie-credentials |
| Dead-man Switch | Datadog + PagerDuty | Revealed enemies are auto-targeted. | cie-monitors-as-code |
| Weighted Parallelization | Cypress + GitHub Actions | Copies split damage evenly across rows. | cms-tl-cypress-parallel |
| Deterministic Replay | Rust + Redis | Cache hits always trigger on the same enemy. | hornvale (project) |
| Monitors as Code | Datadog + Terraform | Traced status is permanent. | cie-monitors-as-code |

## 8. Level-up cards: "Merge a PR"

Three cards per level-up, drawn from the current stage's role (weighted by
bullet weight), with occasional ball or fusion cards. A card shows the bullet
text verbatim, the role title, and dates. Its effect is derived from its tags:

| Tag | Effect |
|---|---|
| ci-cd | Fire rate ("deploy frequency") |
| incident-response | Error-budget regeneration ("MTTR") |
| observability | Reveal radius; traced bonus |
| security | Armour piercing |
| testing | Damage vs Flaky Test and Skipped Check |
| migration | Boss damage |
| cost | XP gain |
| ownership | Max error budget |
| mentoring, leadership | Teammate turret (auto-fires a small ball) |
| architecture | Fusion offered sooner |
| platform, terraform | Ball count |
| backend, serverless, aws, node, typescript, php, drupal, macos, rust | Base damage |
| cross-team | Ball bounces off enemies gain speed |
| documentation | Postmortem shows more detail; small budget regen |
| remaining tags | Base damage |

Magnitude scales with bullet weight. The mapping lives in `design.yaml`; a
test fails if any tag in `content/tags.yaml` has no entry.

## 9. Postmortem (end screen)

Shown at the end of every run:

- Outcome (SLO met / SLO breached) and stage reached.
- Minute-level timeline: stage starts, bosses killed, level-ups, budget hits.
- DORA-style stats: deploys (shots fired), change failure rate (share of
  shots that hit nothing), time to restore (mean time from budget hit back
  to full), lead time (seconds to first boss).
- Every card picked this run, verbatim, grouped by role.
- Summary, PDF link, website, GitHub, LinkedIn, email.

Best outcome is kept in `localStorage` (wrapped in try/catch).

## 10. Accessibility and recruiter affordances

- "Skip to résumé" button always visible; opens the postmortem's résumé
  section directly.
- Pause on Esc/P and on tab blur.
- `prefers-reduced-motion` turns off screen shake and particle effects.
- Card text is DOM, not canvas, so it is selectable and readable by screen
  readers.
- Works at phone width with touch aim-and-release.

## 11. Testing

- `tests/test_game.py`: every `cites` id exists in content (bullet or project id); every content tag
  has a tag effect; every string in `design.yaml` passes the sensitivity lint;
  export produces valid JSON with the expected keys.
- `game/test/*.test.js` (`node --test`): physics collisions, card effect
  derivation, fusion eligibility, boss scripts, postmortem stats.
- Headless simulation: a scripted player with a seeded RNG completes all four
  stages; a player that never fires breaches the SLO in stage 1.

## 12. Out of scope for v1

Meta-progression across runs (beyond best outcome), audio, multiple
characters, leaderboards, and any server component.
